# Repository administrator checklist

These steps require GitHub access to `RootCode-AI/voicelk_ml`. Adding documentation files does not change repository settings. Live settings were not changed or verified as part of this local documentation update.

## Description

In the repository's **About** section, use:

> Sinhala-English text-to-speech research for accessible O/L ICT education: Flask text-to-IPA API, VITS training, synthesis, and evaluation.

Optional topics: `sinhala`, `text-to-speech`, `tts`, `vits`, `nlp`, `accessibility`, `education`, `python`.

## Accept content reports

For an eligible public organization repository:

1. Open **Settings → Moderation options → Reported content**.
2. Enable reporting to repository administrators and choose the available reporter permissions.
3. Save the settings.
4. Confirm an eligible contributor can see the reporting option and administrators know how to review reports.

See [GitHub's instructions for managing content reporting](https://docs.github.com/en/communities/moderating-comments-and-conversations/managing-how-contributors-report-abuse-in-your-organizations-repository).

The [Code of Conduct](../CODE_OF_CONDUCT.md) explains the fallback when reporting to administrators is unavailable. GitHub abuse reporting is not a substitute for a monitored project contact; publish a dedicated private contact when one is established.

## Private vulnerability reporting

Enable **Private vulnerability reporting** in the repository's security settings. Verify that the [private report form](https://github.com/RootCode-AI/voicelk_ml/security/advisories/new) is available and that responsible maintainers receive notifications.

See [GitHub's configuration instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository). Update [SECURITY.md](../SECURITY.md) if a dedicated private contact is established.

## Publish and verify

- Merge the community files into the default branch through the usual review process.
- Confirm the README, license, code of conduct, contribution guidelines, and security policy are recognized by GitHub.
- Enable Issues if needed and verify the bug, feature, and accessibility forms in the issue chooser.
- Open a draft pull request to check the pull request template.
- Confirm the description and content reporting settings separately.
- Recover and preserve missing upstream license notices as described in [third-party notices](../THIRD_PARTY_NOTICES.md) before redistribution.

See [contributing guidelines setup](https://docs.github.com/articles/setting-guidelines-for-repository-contributors/) and [adding a license](https://docs.github.com/articles/adding-a-license-to-a-repository/) for GitHub's community-file guidance.
